Learning Android by Dissecting NeuroFlow

Front matter for Learning Android by Dissecting NeuroFlow. This file is the book's table of contents, its reading-order contract, and its loop budget. It is also the first entry in the binder's manifest, so what you are reading is bound into book.html along with the chapters.

The promise

Most codebase-teaching books fail the same way: they tour the code, the reader follows along, and the reader cannot do it alone afterwards. This book inverts the order. The reader's own code fails in a way they can feel, they invent the fix, and only then do they meet the production version of the idea. Reading NeuroFlow's source is the review step, never the introduction.

The contract

You are assumed to be able to program in another language, and to have never written Kotlin, never opened Android Studio, never shipped a feature. Nothing else is assumed, and no chapter is a prerequisite gate. In exchange, four rules hold for all 22 chapters:

  1. Write your prediction down before you scroll. Every chapter opens with real code, one

question, and one line for your answer. The explanation is withheld until the answer is written. If you skip the prediction you get a book you read, not a skill you have. Chapter 0 makes you create the file your predictions live in.

  1. Type the code; do not copy-paste it. Chapters mark the lines you are allowed to touch and the

files you are not.

  1. Chapters are read in order, because each one is caused by the last. Section 2 of every chapter

is The Gap: the previous chapter's code failing in a specific, demonstrable way. Skipping ahead means reading an answer to a question you have not met.

  1. Kata answers stay in their own tree. solutions/ holds them; a chapter never contains its own

answer key. Reading ahead is a decision you make deliberately, not an accident of scrolling.

Your code lives in app/src/main/java/com/neuroflow/app/lab/ — a fenced package that grows from empty, compiles as part of :app, uses its own lab_ table prefix and its own LabDatabase, is never registered into NeuroFlowDatabase, and is imported by nothing in the app. Its full rules are in app/src/main/java/com/neuroflow/app/lab/README.md (not yet written — Task 3).

Every chapter ends with a verified against footer: the date and the git rev-parse --short HEAD at the moment its last claim was checked against this working tree. When a footer is older than your checkout, re-run the commands that produced the numbers before you trust them.

How the book is bound


bash docs/book/build-book.sh            # bind what exists; WARN about the rest, exit 0
bash docs/book/build-book.sh --strict    # fail (exit 1) if any chapter in CHAPTERS is missing

build-book.sh concatenates the manifest in order — front matter, then CHAPTERS, then back matter — into one HTML document with a print stylesheet (book.css), opening every bound file in its own <section> so a browser's Print → Save as PDF produces a paginated book. The renderer is the script's own: bash and python3 only, no pandoc (absent on this machine, deliberately not installed), no new project dependencies. It renders headings, fenced code, paragraphs, pipe tables, bullet and numbered lists, **strong** and *emphasis*, and inline code spans — and nothing else, so chapters keep their markup plain. Three rules for anyone writing a chapter: a | that must appear inside a table cell is written \| — a DAO query like LIKE '%' || :query || '%' splits fine in a sentence but would break a row; a fence left unclosed is reported on stderr and closed for you; and emphasis only counts when a non-word character sits outside it, so 2 * 3 * 4 and a glob like kata-NN-*.md stay literal while *(not yet written)* becomes italics — put a * that means itself inside backticks regardless. Manifest entries whose file does not exist yet print WARN: missing <path> on stderr and are skipped, so the binder is runnable from today and every later task only has to add its filename to CHAPTERS. --strict is the gate that fails (exit 1) when a chapter named in CHAPTERS is absent; --strict gates chapters only, not the appendices.

Chapter 0 — How to read this book

This chapter has no code to write and no feature to ship. 4. The quarantine command. One grep fences the lab package; the canonical form is the filename form:


grep -rln "com.neuroflow.app.lab" app/src --include='*.kt' | grep -v "/lab/" || echo "CLEAN: no production references"

-l matters: grep -v filters line by line, so on line output it can delete a production file's reference when the matched line itself also names a /lab/ path; on filename output the filter sees only paths, and a production path never contains /lab/. The single quotes around *.kt are load-bearing, not style:


zsh -c 'grep -rn "com.neuroflow.app.lab" app/src --include=*.kt | grep -vc "/lab/"'
zsh:1: no matches found: --include=*.kt
0

Unquoted, zsh tries to expand --include=*.kt before grep ever sees it, aborts, and the pipeline prints 0 — which reads exactly like a passing quarantine check. A silent-false command is the worst kind of documentation bug, because it validates the thing it never tested. Every form of this grep in this book quotes the glob. The trap is shell-shaped, not person-shaped: bash leaves an unmatched glob literal, so the same unquoted command reaches grep as a real flag there and prints an honest 0. The zsh -c wrapper above is how the book ran it; the failure is measured, not hypothetical.

4. 4 GB of Gradle heap plus an emulator does not fit in 7.4 GB of RAM.

gradle.properties sets org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m and kotlin.daemon.jvmargs=-Xmx2048m. With both daemons running free -h reported 1.2Gi available of 7.4Gi; after ./gradlew --stop it reported 4.0Gi, and the AVD was booted in that second state (the emulator also raised its own allocation, Increasing RAM size to 2560MB). A boot attempted while the Gradle and Kotlin daemons were live was not tried, so its cost is not measured on this machine — but with 1.2Gi free and a 2.5Gi VM, the risk is obvious. So: stop the daemons before you boot the emulator. Gradle daemons are respawned on the next invocation, so ./gradlew --stop costs nothing but the next build's startup (row "First build of a session" above is that startup: 21 s).
